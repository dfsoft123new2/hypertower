# 三阶段真实模拟：离线资料与复跑说明

本资料随《I–∞ 全程超详细图文攻略》提供。所有起点均为隔离建立的实验档，没有读取或覆盖真实玩家存档。先看网页“时间实测”中的起点与策略，不能只拿终态数字比较。

## 文件分布

- `P1`：完成 V 的公开测试种子、首次 ε10 基线、VI–X 推进记录、一天等价核对、六档长期检查点和结果。JSON 使用原始旧窗持久表示，不将其误称 HT5 导出字符串。
- `P2`：225000 轮/6600 万太一历史档位的隔离基线、六档原生 HT5 检查点、完整一天原生复验、五轮状态重复证明、低遗产对照与首轮研究路线。
- `P3`：公开合成首圈基线、一天/一周/30 天实际执行记录、已运行到的完整存档与每日进度。年、十年、百年尚未执行完，不填预测值。缓存优化验证另存，仅作方法诊断，没有混入主表原生月结果。
- `原始脚本`：执行与验证所用脚本的原始字节，保留当时的绝对 D 盘路径。
- `内核快照/hypertower`：仅复制运行这些模拟需要的原版本文件；保留文件原始字节与 SHA-256。它不是完整游戏安装包。
- `文件索引.json`：逐文件相对路径、字节数与 SHA-256。文件索引自身不纳入自哈希。

## 基线限制

P1 从公开已完成 V 种子开始，VI 到首次 ε10 实际推进后才计长期天数。P2 预置用户明确给出的历史轮数、太一、720 星与已验证设计；不声称重跑历史 22.5 万轮或人工解题。P3 的设备、研究、八音树和初始资金均明示预置，之后只按公开原生自动策略运行；使用连续重复离线结算，不冒充在线挂机或全局最优路线。

P2 整周期使用固定条件下的状态重复批处理，不是拟合预测。完整一天和远期原生回放报告保留浮点误差；离散轮数、太一、档案、蓝图 ID 等要求严格相同，但不能宣称派生巨数缓存所有位相同。原始差异报告原样保留。

## 便携复跑

需要已有 Node.js（推荐 22 或更新版）。不需要 npm 安装，不连接网络，也不读取游戏浏览器存储。在本目录打开终端：

```text
node 复跑.cjs p1
node 复跑.cjs p2
node 复跑.cjs p2-day
node 复跑.cjs p2-low
node 复跑.cjs p3-resume --days 30
node 复跑.cjs p3-resume --days 365
```

启动器在本资料目录下新建 `复跑输出/时间戳-任务`。它复制内核快照、检查点和脚本，只把工作根路径改成这份新目录，再运行。原始脚本和原始检查点不变，游戏算法不变。实际执行副本因路径替换会有不同的脚本哈希，原始版本哈希仍可查文件索引。P2 主任务会先重建周期证明再输出六档；`p2-day` 是较慢的一整天原生复验；`p2-low` 重跑低遗产研究路线与对照。

P1 百年、P3 远期可能耗时很长，程序输出的是已处理到的游戏时长，不是承诺剩余墙钟时间。P3 默认从包内已完成的30天存档和报告载入：`--days 30`只做重载校验，不推进到第31天；`--days 365`才会从30天继续到累计365天。目标天数是从原基线累计计算，不是额外增加的天数。P3起点与实测细节另见`P3/实验说明.md`。

P3每日检查点保存在终端显示的新运行目录内，默认位置为`walkthrough-work-20261101/simulation-p3-resume-checkpoint.json`。旧运行中断后，在本资料目录使用其指针继续，例如：

```text
node 复跑.cjs p3-resume --days 365 --checkpoint ".\复跑输出\上次任务目录-p3-resume\walkthrough-work-20261101\simulation-p3-resume-checkpoint.json"
```

把`上次任务目录-p3-resume`替换成实际文件夹名。`--checkpoint`也可用绝对路径；相对输入路径按启动命令时的当前目录解析。启动器从旧指针读取存档和报告，但另建新的复跑输出目录写后续结果，旧运行检查点不变。若使用`--save`和`--report`，须同时指向同一时点的数据对；通常优先使用带SHA校验的`--checkpoint`。`--prefix`如为相对路径，按新隔离运行目录解析；不传时使用上面的默认位置。

P3响应中断时会在小时步长边界保存；强制结束进程前先确认最近检查点已完整写成。运行结果不会自动导入游戏，也不会代替玩家操作正式存档。原始脚本保留当时固定D盘路径用于核验，便携运行应通过`复跑.cjs`，不直接执行原始脚本。

## 复核顺序

1. 对照文件索引检查输入与内核 SHA-256。
2. 对照网页确认基线、研究、携带、资金、自动策略和时间单位。
3. 读取结果 JSON，核对目标秒数和完成标记；`progress`/`partial` 文件表示途中记录，不替代最终结果。
4. 核对对应 checkpoint 的纪元、轮数、ε、圈号、当前劫和资源。若需要游戏界面查看，先备份真实进度，在隔离环境导入适用格式。
5. 改变策略或版本后另建实验。保留新的输入、动作、结果与限制，不沿用原表名隐去变化。
